# Cycles parity ledger

Full Cycles parity is the intended outcome, explicitly requested by Jeremy.
The reference is the pinned upstream revision
`a456b761034dda42c32eef9f4aae0fa5a5c9f604`; each new behavior needs comparison
with original Cycles code and, ultimately, complete reference renders.

Hard constraints: unchanged shipped CodeBrix.WebGpu.Native binaries, native C++
host/backend, no Slang, Android API 33 minimum, the requested desktop/mobile RIDs,
permissively licensed redistributable dependencies, and no Git commits/pushes.
A need to modify WebGPU itself is a decision point, not an implicit workaround.

Release licensing: active builds use the filtered pinned Cycles snapshot and
independent Apache-2.0 host atomics. Multithreaded atomic/film tests pass; both
native proof scenes retain bitwise-identical CPU and GPU films after migration.
Dependency/source-containment and shipping-package checks remain distinct gates.
See [the license tracker](RELEASE-LICENSE-PLAN.md) and generated notices.

Material-driven, multi-bounce image comparisons now exist for a limited scene.
WGSL camera/sampling now feeds those paths without native per-path inputs.
Finite-light NEE/MIS now uses a second dispatch for shadow traversal, with
all per-path work on the GPU. The shared native library now adds bounded batches
and GPU film accumulation without changing the images. Actual Cycles device
registration, scheduler controls, native camera, closest intersection and
constant and selected SVM background/film now exist. Native static-triangle
shader-data preparation now has original CPU and four-device GPU checks.
Selected native surface SVM closure evaluation now passes against the CPU on Linux.
The selected surface dispatch now completes a repeated multi-bounce native-scheduler image, with independent original CPU comparisons and complete command replay on four GPUs. Static-triangle attributes now have original CPU comparisons and a UV-driven full render. Next are production image/cache and broader closure coverage, then direct-light/shadow/MIS dispatches, alongside
investigation of numerical differences. Each gate keeps
prior evidence reproducible. The full renderer remains the objective; passing
a limited image gate is permission to continue, not a declaration of parity.

The initial [machine-readable compatibility inventory](../compatibility/README.md)
now records 1,011 declarations, all nine platform requirements and dependency
tracks. Its native metadata is checked against Clang declarations and a compiled
Linux x64 probe. The evidence registry is refreshed after implementation changes, with bounded mappings
for 16 kernels, five closures, four attribute opcodes, six image/environment
opcodes and the normal/tangent continuation; no full requirement is marked verified. Native
node registration, properties, additional conditional features and most behavior
classification remain P00 work. Compiler metadata alone does not establish renderer feature coverage.

## Open items from the native ABI additions

These were found while closing the scene-host ABI gaps (native/host/ABI.md).
Phase E3 closed them on Linux. The shadow terminator (gate, replays and the
managed scenes with default offsets) is confirmed on the Samsung, HP and Pixel;
edits after a render and device recovery are validated on Linux.

| Item | Status |
| --- | --- |
| Object `tfm` changed after a mesh's first render | CLOSED (Linux). Confirmed not applied before the fix (the static-BVH path bakes a single-user mesh with its object transform). The host now keeps the authored attributes of geometry a render may bake and restores them before a geometry edit or a render whose bake would differ, so Cycles' own update re-bakes or instances it (`native/host/host_edits.inc`). Object `tfm`, object/camera/deformation motion added or removed, motion blur, materials, lights, mesh replacement, instancing, attributes and `smooth` flags: `scene_edit_gate.py`, CPU bit-identical to a fresh host, WebGPU practical. Refused explicitly (`CBC_NOT_READY`): edits of a baked volume with voxel data. |
| A host is dead after a device error | CLOSED (Linux). The next render recovers an intact WebGPU device (error cleared, scene fully re-uploaded, "Device recovered" status event); `scene_edit_gate.py` recovers after a rejected depth pass and an orthographic camera and matches a fresh CPU render. A device that cannot recover (lost WebGPU device, CPU or Metal device error) keeps failing with "Host faulted"; `CyclesScene.IsFaulted` is cleared by a successful render. |
| WebGPU smooth shadow-terminator offsets | CLOSED (Linux). Object geometry offset (default 0.1) and shading offset 0 to 1 are implemented in WGSL under scene specialization (`SHADOW_TERMINATOR_GEOMETRY`, `SHADOW_TERMINATOR_SHADING`); `shadow_terminator_gate.py`: 10 sun/point, instanced and moving/deforming cases against the original CPU kernels, with replays. Shading offsets above 1 are rejected before dispatch. The managed validation scenes and the glTF tool keep the default offsets. |
| Intel Mesa `shade_surface_light` compile crash (spot/area after point) | PARTLY MITIGATED (Linux Intel UHD, Mesa 25.0.7). Diagnosed as the known intermittent `brw_opt_combine_constants` driver bug (out-of-bounds read with a garbage register number), not a WGSL error. Spot after point adds no specialization bit and does not recompile; the GPU ABI test renders point, spot and sun again. The `LIGHT_AREA` recompile crashed 3 of 4 cold runs before and 0 of 7 after the area light's arcsine series became one loop; a further recompile after an area light (object motion) still crashed 2 of 4, so the GPU ABI test renders its area light on the CPU only. A driver fix or a smaller lamp stage remains open. |
